# 08 2時点の差分の穴：走っている間の作業場の出来事（2026-09-27・母艦）

guardrun の差分は before/after の2時点だけなので、**途中で作って消したもの**が見えない。
走っている間の出来事を、壁の外から特権なしで受け取れるかを測った。コードは `fsev/`。
**guardrun にはまだ入れていない。**

## 判定基準（走らせる前に書いた）
3通り（途中で書いて消す・フォルダごと作って消す・書くだけ）を guardrun の壁の中で各10回。
深いフォルダの回で d・d/e・d/e/f・d/g の4つが「作って消した」として 10/10 取れること、
tmp.txt も 10/10、書くだけの回で差分と出来事が合うこと。取りこぼしたら回数と、落とした印が出たかを報告。

## 結果

| 通り | 2時点の差分 | Mac FSEvents（10回） | Linux inotify（10回） |
|---|---|---|---|
| 途中で書いて消す | a だけ（tmp.txt は見えない） | 10/10 | 1回の予行で取れた（10回は未） |
| フォルダごと作って消す | 何も出ない（青） | **10/10** | **3/10**（d/e・d/e/f を落とす） |
| 書くだけ | b・前.txt | 10/10 合う | 1回の予行で合った |
| 落とした印が出た回 | — | 0 | **落とした7回のうち1回だけ**（6回は黙って落とした） |

- Mac: FSEvents（CoreServices を ctypes で・特権なし・フォルダの下を丸ごと見張る）。macOS 26.5（Darwin 25.5）。
- Linux: inotify（ctypes・特権なし・フォルダごとに見張りを足す）。OrbStack 7.0・Ubuntu 22.04・別ユーザ+bwrap。
- Linux の取りこぼしは仕組みの形：新しいフォルダに見張りを足す前に中身が作られて消えると、後から補う手も届かない。
  しかも多くは「あふれ」「見張れなかった」の数に出ない＝**黙る**。このまま入れてはいけない。

## 言えること・言えないこと
- 言える: Mac では特権なしで、途中で作って消したものを 10/10 拾えた（2時点の差分では 0）。
- 言えない: 誰が（どのプロセスが）したか。読んだこと。Mac の FSEvents は出来事をまとめるので順番・回数は正確でない。
  「誰が」は Mac は eslogger、Linux は auditd/eBPF で、どちらも管理者権限が要る。
- Linux は inotify のままだと黙って落とす。fanotify（フォルダの下をまとめて見張れる）は特権が要る。

## 次
1. Mac の FSEvents を guardrun に組み込む（受領証 実測.出来事）。落とした印（Dropped/MustScanSubDirs）は数で出す
2. Linux は、取りこぼしうる場面を数で出す形に直すまで入れない（または「深いフォルダは取りこぼしうる」と受領証に明記）
3. 組み込んだら、壁の証明・印の試験・実測で退行が無いかを確かめる
