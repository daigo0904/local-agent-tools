# Mac 上での比較実験の設計（2026-09-30）

**本ファイルは設計のみ。実行は一切しない**（別プロセスが J1 検証のため推論サーバ・実機を占有中）。

## 背景

⑤の比較実験は Linux（OrbStack コンテナ）で ABC 72試行を完了した（18）。
残る「別環境での再現」は本物 Ubuntu の GitHub Actions で行う予定だったが、
利用枠切れ（支払い失敗／spending limit）で workflow は未実行のまま停滞している（20）。

その代替として、**手元の Mac 上で macOS 版の ABC 比較を行う設計**をここに固定する。

## 目的と、正直な限界

### 示せること

- macOS 実装（19 の見届け役分離版）について、Linux 側（18）と同じ構造の比較ができる：
  - C（OS境界の上乗せ）が攻撃操作をその場で拒否するか
  - C が B より正当作業を止めないか
  - C の上乗せに要する時間が B の 2倍を超えないか
- 19 の単体検証（37/37、壁の検証12/12）は「壁が効くか」だけで、
  **A/B/C の同時比較・誤拒否率・時間はまだ測っていない**。本実験はそれを埋める。

### 示せないこと（Ubuntu 代替としての弱さ。必ず結果と併記する）

- **「別環境での再現」の主張は弱くなる。** 20 が Ubuntu 実機を求めた理由は
  「Mac 固有の実装に寄った結果では一般性を主張できない」ため。
  本実験は OrbStack カーネルとは別の実装系（Darwin 25.5.0 / Seatbelt）での比較ではあるが、
  **カーネル層の方式そのものが違う**（Landlock → Seatbelt）ので、
  18 の結果の「再現」ではなく「並行実装での対比」として扱う。
- Landlock 固有の振る舞い（ABI 差、古いカーネルでの劣化）は Mac では一切検証できない。
- Ubuntu 実機実験は廃止せず、枠が戻ったら 20 の workflow をそのまま実行する。
  本実験はその穴埋めではなく、macOS 実装自体の評価として独立させる。

## 構成の調整（A/B/C を macOS に写す）

05 の定義を踏襲するが、境界機構が異なるので以下のように写す。

| 腕 | Linux 版（18） | macOS 版（本設計） |
|---|---|---|
| A. 防御なし | 直接実行 | 直接実行（uid 分離も sandbox-exec も掛けない） |
| B. 現行 guardrun | uid 分離＋bwrap＋見届け役（Landlock 適用のみ外した比較用コピー） | uid 分離＋sandbox-exec（既存規則）＋見届け役（**記録保護・シグナル規則の上乗せのみ外した比較用コピー**） |
| C. OS境界を足す | 同じ固定ソースで Landlock を適用 | 同じ固定ソースで 19 の記録保護・same-sandbox シグナル規則を適用 |

- B/C は `comparison/prepare.py` と同じ手順で固定コピーを作る。
  現行 `~/bin/guardrun.py`（SHA256: `b42333d1…90bf`、19 参照）をバイト単位でコピーし、
  B では上乗せ規則の注入箇所を空にする。**差し替え箇所が一意でなければ準備を拒否する**（17 と同じ）。
- 固定先は `comparison/frozen-<日付>-mac/`、manifest.json にソースの SHA256 と差分を記録。
- **運用中の guardrun.py は変更しない。** 無効化スイッチ等を本体に追加しない（17 の原則）。
- なお B/C の差は「Seatbelt の上乗せ規則の有無」であり、uid 分離・基本 Seatbelt 規則・
  一時領域の配置・環境変数付け替えは両方で維持する。B は「過去の版」ではなく
  「現行版から上乗せだけを取り除いた比較用構成」として明記する（17 と同じ書き方）。

## 測る3つ（05 そのまま）

1. **防げた数** … 攻撃ケースのうち、その場で拒否できた件数
2. **正当な作業を止めた数** … 正当作業ケースのうち、誤って止めた件数
3. **処理時間** … 同じ作業を通したときの壁時計

攻撃操作は 18 と同じ4種：**記録偽造・削除・切り詰め・FIFO差し替え**。
正当作業は同じく4種：**作業場内の作成・mkdir・rename・unlink**。
攻撃は操作成功後に exit 3、C の拒否は exit 1＋PermissionError＋
見届け記録の起動・閉じ込め・終了の保存で確認（終了0だけを見る採点はしない）。
正当作業は全ファイル内容も照合する。

## 手順と試行数

1. `prepare.py` で固定 B/C を作り、予備試験（preflight 相当）を実施。
   判定：同じ偽造操作が B で成功・C で拒否され、正当な作成が両方で通ること。
   操作ハッシュは各ケースで同じ、ソースハッシュは B/C で異なること（17 と同じ基準）。
2. 予備試験一致後に本計測。**ABC/BCA/CAB 順で8ケースずつ、計72試行**（18 と同数）。
3. 攻撃対象は実際の見届けファイルとし、外側の採点とファイル状態を別々に照合する。
4. 中断の検知：**完了行（complete=72, matched=72）とログのバイト増分の両方**で完了を確認。
   落ちたアームの結果は集計に混ぜず破棄して再実行する。
5. 実験中は対象の実行を他プロセスと同時に走らせない
   （guardrun 実走や J1 など、別プロセスの計測との重複を事前に確認してから開始する）。

## 判定基準（走らせる前に固定。05/18 を継承）

- **C が B より「正当な作業を止めた数」を増やしたら、C は不採用。** 防げた数がいくら増えても。
- **C の処理時間（正当作業の中央値）が B の 2倍を超えたら、その旨を必ず併記する。**
- **A で防げてしまう事例は事例として弱い。** そういう事例は数えてから外す。
- C/B の時間比が 2 倍未満でも、**反復が短い・他負荷を統制していない場合は速度改善を主張しない**（18 と同じ留保）。
- B が偽の成功を受理したか／事後検知で済んだかは、C の上乗せの意味の説明として区別して報告する
  （18 で「その場拒否」と「事後検知」を分けたのと同じ扱い）。
- **負けた結果（C が不採用基準に触れた場合）も同じ形で報告する。**

## 言えないこと（結果に必ず付ける範囲）

- 今回の4操作＋4正当作業だけから一般的な誤拒否率は言えない（18 の留保を引き継ぐ）。
- この Mac（Darwin 25.5.0）での実測であり、他の macOS 版は未検証（19 の留保）。
- Ubuntu 実機での再現ではない。18 の「残る範囲」（古い ABI、別カーネル、シグナル攻撃の網羅、
  業務課題に基づく正当操作の拡充）は本実験では一切縮まらない。
