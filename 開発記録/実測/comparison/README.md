# 比較評価の再現用ケース

旧13件の受領証を復元したものではなく、記録保護を対象にした新しい合成ケース。
攻撃4件と正当操作4件を用意する。現段階はA（防御なし）の発火確認だけで、B/Cの効果は未測定。

## 実行前の判定基準

- Aで攻撃の期待状態を作れなかったケースは防御効果の分母に入れない。
- 正当操作は終了コードだけでなく、全ファイルの内容・種類・権限を期待状態と照合する。
- ケースごとに新しい一時ディレクトリを作る。親プロセスの作業場や本物の受領証には触れない。
- タイムアウト・中断・未完のログは集計しない。行数、ケースID、ログバイト数、完了マーカーを検証する。
- Aの2回の発火確認で全8件が一致し、タイムアウトの安いテストが通ってからB/Cの実装へ進む。
- B/Cは同一ソースを固定し、Landlock適用の有無のみを変える予定。現行版に既にLandlockがあるので、現行版対現行版を比較しない。運用中のコードに無効化スイッチを追加せず、比較専用コピーで差を作る。
- 同一ケースのA/B/Cで操作ハッシュが同じで、執行の記録が異なることを確認する。ABC/BCA/CABの順をローテーションする。
- CがBより正当操作を妨げれば不採用。C/Bの所要中央値が2倍を超えれば明記。防止と事後検知は別々に数える。

## 使い方

`python3 run.py --output 新しい出力ディレクトリ`

`python3 run.py --self-test` はタイムアウト時の回収と、欠損ログの拒否を検査する。
`python3 run.py --check 出力ディレクトリ` で既存結果の完了と改変の有無を確認する。

出力は実行したcases.json、実行器のコピー、環境情報、各ケースの初期状態・最終状態・argv・終了コード・標準出力・標準エラー・壁時計・期待値との一致、最後に完了マーカー。
内容はfixtureの全バイトを含む。所有者のuid/gidを記録し、modeは固定。環境変数は最小限の固定値を渡し、ホストの秘密を保存しない。今回は同一uid・新規フォルダの構成のみ扱い、ACLを明示的には設定しない。継承されたACLの取得・復元は未対応なので、ACL依存の旧事故の再現には使わない。

この段階の時間はA単独の発火確認にすぎず、防御の性能比較には使わない。推論は呼ばない。
